The core shift: a decision is not a prompt. It's a contract.

A text LLM returns prose. Your code then has to guess whether the prose means yes — string matching, `if "refund" in reply`, silent failures. That guessing layer is where AI features quietly die.

A typed decision inverts it. Unstructured state in, a typed answer out — a choice from your named set, a score on your rubric, a probability. Your code doesn't parse it. Your code compares it. And every answer comes with confidence attached.

The JEVLINE Loop™ — the operating spine

Everything in this system is one of four steps. Memorize it.

ASK → SHAPE → CALIBRATE → GATE
A

ASK

One narrow, independent question — never the mega-question. Ask facts, not decisions.

S

SHAPE

Pick the answer shape your code can consume: Noul for gates, Choice for routers, Score for ranking.

C

CALIBRATE

Sweep the threshold on your own labelled cases. A threshold you haven't plotted is one you don't own.

G

GATE

ALLOW / REVIEW / REFUSE in code — never a bare yes/no. When in doubt, do the reversible thing.

The three ingredients of a confident mistake

A wrong decision is a bug. A confident wrong decision wired to an irreversible action is an incident. Every decision-layer blow-up needs all three — remove any one and it becomes a log line instead of an outage:

1 · Uncalibrated threshold

The number 0.9 was a teaching example in someone else's README. Half your auto-routes are wrong.

2 · No review path

The only outcomes are auto-allow and crash. There's nowhere for "I'm unsure" to go.

3 · Action-mapping error

The label was right, the action was wrong. Independent gate studies keep finding this is the #1 source of bad decisions — and almost nobody tests it.

The 30-minute quick start

  1. Pick one branching step doing a string match.
  2. Write the state and one Noul question your code can branch on.
  3. Call it once and log the probability — wire nothing yet.
  4. Label ten real cases. Check what a 0.9 threshold would have done.
  5. Only then add the gate: allow / review / refuse.

That's a real decision layer. Everything else is refinement.
